# UI 개선 개발 계획서 (v0.2, 승인됨)

> 대상: iOS 앱 `ios/PitchEye`. 브랜치 `ios/ui-redesign`.
> 2026-10-10 승인. 결정 사항은 8장.

## 1. 왜 바꾸는가
지금 화면은 측정값을 나열한 점검용 화면이라, 만든 사람도 무엇을 눌러야 하고 결과가 어디 나오는지 알기 어렵다.
앱을 켜면 **할 일이 버튼으로 바로 보이고**, 촬영 전에 **무엇을 준비해야 하는지 안내받는** 구조로 바꾼다.

## 2. 누가, 어디서 쓰는가
- 사용자: 경기장에서 폰을 설치하는 사람 (팀원, 이후 심판·리그 운영자)
- 환경: 낮, 야외, 햇빛 아래. 한 손으로 조작. 설치 후에는 폰을 만지지 않는다.
- 그래서: 흰 바탕, 진한 글씨, 큰 버튼, 적은 색.

## 3. 범위
### 한다
- 홈 화면 (버튼 3개)
- 촬영 전 안내 (4단계, 건너뛰기 가능)
- 촬영 화면 재배치
- 촬영 결과 화면
- 촬영 설정 화면
- 공통 디자인 규칙 (색, 글자, 모서리)

### 하지 않는다 (이번 PR에서)
- 링버퍼, 챌린지 버튼, STRIKE/BALL 판정 화면 (기능이 아직 없음)
- 지난 촬영 기록 보관 (지금은 방금 끝난 결과만 보여준다)
- 다크 모드
- 실제 값이 없는 설정 항목 (장식용 설정은 만들지 않는다)

"촬영 시작"이 지금 하는 일은 **240fps 캡처 측정**이다. 링버퍼·판정이 붙으면 같은 버튼이 그 기능을 시작하게 된다.

## 4. 화면 구성

### 4.1 홈
| 요소 | 내용 |
|---|---|
| 상단 | 앱 이름 `PitchEye`, 한 줄 설명, 기기 상태 표시(240fps 지원 / 미지원) |
| 주 버튼 | **촬영 시작** — 검정 바탕 흰 글씨, 화면에서 가장 큼 |
| 보조 버튼 | **촬영 설정**, **사용 안내** — 흰 바탕, 얇은 테두리 |
| 하단 | "참고용 도구입니다. 최종 판정은 심판이 합니다." |

기기가 240fps를 지원하지 않으면 촬영 시작을 누를 때 이유를 알려준다 (버튼을 흐리게만 두지 않는다).

### 4.2 촬영 전 안내
촬영 시작을 누르면 나온다. 한 화면에 한 가지씩, 4단계.

| 단계 | 제목 | 내용 |
|---|---|---|
| 1 | 설치 위치 | 백네트 뒤, 약 3m 높이. 홈플레이트 전체와 양쪽 타석이 화면에 들어오게 한다. |
| 2 | 단단히 고정 | 촬영 중 폰이 움직이면 그 촬영은 쓸 수 없다. 고정한 뒤에는 만지지 않는다. |
| 3 | 발열과 배터리 | 직사광선을 피하고 외부 배터리를 연결한다. 방해 금지 모드를 켠다. |
| 4 | 촬영 동의 | 선수·심판·구장의 동의를 받았는지 확인한다. 결과는 참고용이다. |

- 오른쪽 위 **건너뛰기**: 바로 촬영으로 넘어간다.
- 아래 **다음** / 마지막 단계는 **촬영 시작**.
- 마지막 단계에 **다음부터 보지 않기** 선택. 설정에서 다시 켤 수 있고, 홈의 "사용 안내"로 언제든 다시 볼 수 있다.
- 안내 문구는 `docs/capture-protocol.md`와 같은 내용을 쓴다.

### 4.3 촬영 화면
- 카메라 미리보기를 크게.
- 위: 촬영 시간, 상태 한 줄 (정상 / 프레임 빠짐 / 발열 높음)
- 아래: 숫자 4개 (실측 fps, 빠진 프레임, 버려진 프레임, 발열), **촬영 끝내기** 버튼
- 촬영 중에는 화면이 꺼지지 않는다 (지금과 같음).

### 4.4 촬영 결과
촬영을 끝내면 나온다.
- 한 줄 요약 (예: "30분 동안 빠진 프레임 없이 촬영했습니다")
- 1분·10분·30분·종료 시점 기록
- **결과 보내기**, **홈으로**

### 4.5 촬영 설정
지금 실제로 의미가 있는 것만 둔다.

| 항목 | 종류 |
|---|---|
| 촬영 전 안내 표시 | 켜기/끄기 |
| 촬영 사양 (1920×1080, 240fps) | 읽기 전용 |
| 이 기기 (모델 코드, iOS 버전, 지원 여부) | 읽기 전용 |
| 지원 포맷 목록 | 읽기 전용, 접힘 |

링버퍼 길이, 저장 위치, 타자 신장 등은 해당 기능을 만들 때 추가한다.

## 5. 디자인 규칙
| 항목 | 규칙 |
|---|---|
| 바탕 | 흰색 `#FFFFFF`, 구역 구분은 아주 옅은 회색 `#F7F7F5` |
| 글자 | 본문 `#111111`, 보조 `#787774`. 순수 검정은 쓰지 않는다 |
| 테두리 | 1pt `#EAEAEA`. 그림자는 쓰지 않는다 |
| 강조색 | 없음. 주 버튼은 검정. 색은 **상태 표시에만** 쓴다 (정상 초록, 주의 주황, 위험 빨강의 옅은 톤) |
| 모서리 | 버튼·카드 모두 16pt로 통일 |
| 글꼴 | 시스템 글꼴(SF Pro). 숫자는 고정폭 숫자 |
| 아이콘 | SF Symbols. 이모지는 쓰지 않는다 |
| 버튼 | 주 버튼 높이 64pt 이상, 보조 버튼 56pt. 누르면 살짝 눌리는 반응 |
| 움직임 | 화면 전환과 버튼 반응만. 장식용 애니메이션은 없다. "동작 줄이기" 설정을 따른다 |
| 문구 | 짧은 동사로 시작. "~하세요" 남발 금지, 느낌표 없음 |
| 화면 모드 | 라이트 고정 (야외 가독성, 요청 사항) |

### 스킬 사용에 대해
설치된 스킬을 검토해 이 작업에 맞는 것만 썼다.
- **brainstorming**: 구현 전에 설계를 먼저 합의하는 절차
- **minimalist-skill**: 흰 바탕, 단색 위주, 색 절제, 얇은 테두리, 그림자·그라디언트·이모지 금지 원칙
- **taste-skill**: 흔한 AI 디자인 버릇(보라색 그라디언트, 장식용 점·라벨, 색 남발) 금지 목록

쓰지 않은 것: 웹 전용 스킬(brutalist, soft, redesign, stitch, gpt-tasteskill 등)은 CSS·웹 프레임워크 기준이라 네이티브 iOS 앱에는 그대로 적용할 수 없다. 이미지 생성 스킬은 이 환경에 이미지 생성 도구가 없어 쓸 수 없다. 위 세 스킬의 원칙을 SwiftUI와 Apple 기본 규칙에 맞춰 옮겼다.

## 6. 구현 계획
| 순서 | 작업 | 파일 |
|---|---|---|
| 1 | 디자인 규칙 (색, 버튼 모양) | `Theme.swift` (신규) |
| 2 | 홈 화면 | `HomeView.swift` (신규) |
| 3 | 촬영 전 안내 | `GuideView.swift` (신규) |
| 4 | 촬영 화면, 결과 화면 | `CaptureView.swift` (신규, 기존 `ContentView.swift`에서 분리) |
| 5 | 설정 화면 | `SettingsView.swift` (신규) |
| 6 | 화면 연결, 기존 화면 제거 | `PitchEyeApp.swift`, `ContentView.swift` 삭제 |

`CaptureController`, `FrameStats`, `Requirements`는 그대로 쓴다. 측정 로직은 바꾸지 않는다.

## 7. 확인 방법
- 빌드 성공 (기기용, 시뮬레이터용)
- 시뮬레이터에서 홈 → 안내 4단계 → 건너뛰기 → 설정 화면을 직접 눌러 확인하고 화면을 남긴다
- "다음부터 보지 않기"를 켠 뒤 앱을 다시 실행해 안내가 안 나오는지 확인
- **촬영 화면과 결과 화면은 카메라가 필요해 실기기에서만 확인된다.** 아이폰에서 확인 요청

## 8. 결정된 것 (2026-10-10)
1. **촬영 방향**: 가로 설치. 촬영 화면은 가로에서 미리보기를 왼쪽에 크게, 숫자와 버튼을 오른쪽에 둔다. 홈·안내·설정은 세로와 가로 모두 지원한다.
2. **홈 버튼**: 촬영 시작 / 촬영 설정 / 사용 안내 3개.
3. **안내**: 4단계 그대로.

## 9. 다음에 추가할 후보 (기능이 생길 때)
- **구도 확인 단계**: 촬영 시작 전에 미리보기 위에 홈플레이트가 들어와야 할 영역을 표시한다. 카메라 보정 방식이 정해진 뒤.
- **촬영 기록 버튼**: 클립 저장(링버퍼)이 생긴 뒤.
- **챌린지 버튼과 판정 결과 화면**: 판정 기능이 생긴 뒤.
