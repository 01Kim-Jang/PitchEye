# 촬영 프로토콜 (초안 v0.1)

> 목적: 1~2주차에 240fps 영상 200구 이상을 **같은 조건으로** 모으기 위한 현장 절차.
> 수치 중 "권장"은 실측 전 가정입니다. 첫 촬영 후 이 문서를 고칩니다.

## 1. 준비물
- 240fps 지원 아이폰 (보유자 `[__]`), 여분 저장 공간 확인
- 삼각대 또는 백네트 고정 마운트 (약 3m 높이까지), 외부 배터리
- 줄 존 틀 (3장), 줄자, 수평계, 마스킹 테이프
- 촬영 동의서 (`consent-checklist.md`), 메타데이터 기록지 (5장)

## 2. 카메라 설치
- 위치: **백네트 뒤, 약 3m 높이**. 구장별 실제 가능 위치·높이는 `[__]` — 설치할 때마다 줄자로 재서 기록한다.
- 홈플레이트 **전체와 타석 양쪽**이 프레임에 들어와야 한다 (보정 기준점).
- 촬영 중 폰이 움직이면 그 세션의 보정이 무효가 된다. 고정 후 건드리지 않는다.
- 설치 후 사진 2장: 폰이 설치된 모습, 폰 화면에 잡힌 구도.

## 3. 카메라 설정
- 1080p, 240fps
- 초점·노출 **고정** (촬영 중 자동으로 바뀌지 않게). 권장.
- 셔터 속도는 가능한 빠르게 (공 번짐 감소). 구체값 `[__]` — 첫 촬영에서 번짐 정도를 보고 결정.
- 방해 금지 모드, 화면 자동 잠금 해제, 저전력 모드 끔

## 4. 줄 존 틀
- 용도: 홈플레이트 위에 세워 공이 존을 통과했는지 영상으로 판독하는 **정답 기준**.
- 폭: 홈플레이트 폭(17인치 = 43.18cm)에 맞춘다.
- 상·하단 높이: 타자 신장 비율로 정한다. 비율 값 `[__]` (사용할 규정 확인 필요).
- 재질·기둥 간격·줄 굵기 `[__]` — 제작하면서 사진과 치수를 이 문서에 추가한다.
- 설치할 때마다 수평계로 수직·수평 확인, 홈플레이트 앞면과의 거리 기록.

### 결정이 필요한 것
1. **정답을 어떤 영상으로 판독하는가.** 백네트 뒤 카메라는 포수·심판에 가려 틀 통과 순간을 못 볼 수 있다. 정답 판독용 **보조 카메라(측면 또는 위)** 가 필요한지 첫 촬영에서 확인한다. `[__]`
2. 틀을 세운 상태에서 타자를 세울 수 있는가 (스윙 금지 조건 등). `[__]`

## 5. 촬영 구성
가림이 최대 리스크이므로 조건을 나눠서 찍는다. 조건별 목표 구수 `[__]`.

| 조건 | 포수 | 심판 | 타자 | 목적 |
|---|---|---|---|---|
| A | 없음(네트) | 없음 | 없음 | 가림 없는 기준 궤적 |
| B | 있음 | 없음 | 있음 | 포수 가림 |
| C | 있음 | 있음 | 있음 | 실제 경기 조건 |

- 세션 시작 시 **보정 촬영** 10초: 빈 홈플레이트 + 줄 존 틀이 보이는 상태.
- 투구 번호를 소리 내어 말하거나 번호판을 보여 영상과 기록지를 맞춘다.

## 6. 메타데이터 (투구 1개 = 1행, CSV)
`date, venue, session_id, pitch_no, device, camera_height_m, camera_distance_m, condition(A/B/C), batter_height_cm, batter_side(L/R), truth(strike/ball/unknown), truth_source, note`

- 파일명: `YYYYMMDD_구장_세션번호.mov`
- 영상은 Git에 올리지 않는다. 보관 위치 `[__]`.
