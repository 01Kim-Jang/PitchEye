# 공 크기 측정 실험 (촬영 방법)

> 목적: 화면에서 잰 공의 크기로 거리를 알 수 있는지 확인한다.
> 배경: [카메라 1대 복원 실험](experiments/2026-10-13-monocular-reconstruction-sim.md)에서, 공 크기를 항상 1px 크게 재면 통과 지점 상하 오차가 약 22cm가 된다는 계산이 나왔다. 이 실험으로 실제 치우침이 얼마인지 본다.

구장이 없어도 된다. 야외 낮, 넓은 공터면 충분하다.

## 준비물
- 아이폰 (PitchEye 앱), 삼각대나 고정할 받침
- 야구공 1개, 줄자 (10m 이상이면 좋다)
- 공을 올려 둘 받침 (공이 배경과 겹치지 않게, 가능하면 어두운 배경)

## 앱 설정
- 촬영 설정 → 최대 노출 시간. **자동**으로 한 번, **1/2000초**로 한 번 찍는다. 번짐 차이를 보기 위해서다.
- 촬영 화면의 "노출" 표시가 실제 노출 시간이다. 영상을 저장할 때 정보 파일에 함께 기록된다.

## 촬영 1: 멈춰 있는 공
폰을 가로로 고정하고, 렌즈에서 공 중심까지의 거리를 줄자로 잰다.

| 거리 | 메모란에 적을 값 |
|---|---|
| 2m | `2m` |
| 3m | `3m` |
| 5m | `5m` |
| 7m | `7m` |
| 10m | `10m` |

- 거리마다: 메모를 적고 **영상 녹화** → 2~3초 뒤 **녹화 끝내기**.
- 공은 화면 가운데 근처에 둔다. 5m에서는 화면 가장자리에도 한 번 더 찍는다(메모 `5m-edge`). 렌즈 왜곡을 보기 위해서다.
- 거리는 cm 단위까지 정확히 잰다. 이 실험의 정답이 이 숫자다.

## 촬영 2: 움직이는 공
- 폰을 고정하고, 카메라 쪽으로 공을 던진다(폰 옆으로 지나가게, 폰을 맞히지 않게).
- 던지는 사람 뒤가 아니라 **받는 쪽 뒤**에 폰을 둔다. 실제 설치와 같은 방향이다.
- 5~10구. 메모는 `throw`. 노출 자동으로 한 묶음, 1/2000초로 한 묶음.
- 가능하면 홈플레이트 위치를 정해 두고, 폰에서 그 지점까지의 거리와 폰 높이를 잰다.

## 영상 옮기기
1. 홈 → **저장한 영상** → 각 영상의 보내기 버튼 → AirDrop으로 Mac에 보낸다. 영상(.mov)과 정보 파일(.json)이 함께 간다.
2. Mac에서 `data/raw/ball-size/` 폴더에 넣는다. 이 폴더는 git에 올라가지 않는다.

## 분석 실행
```bash
cd ml
.venv/bin/python ball_size.py ../data/raw/ball-size
```
- 영상마다 정보 파일의 메모를 보고 멈춘 공(`3m`, `250cm`, `5m-edge`)과 던진 공(`throw`)을 나눈다. 메모가 비어 있으면 파일 이름을 본다.
- 멈춘 공을 자동으로 못 찾으면 위치를 알려준다: `--roi 영상이름=x,y,w,h` (공을 감싸는 상자, px)
- 결과 표가 화면에 나오고, 프레임별 측정값은 `ml/runs/ball-size/*.csv`에 남는다.

결과에서 볼 것:
- **치우침(절편)**: 멈춘 공 지름을 거리의 역수에 직선으로 맞췄을 때의 절편(px). 0에 가까워야 한다. 카메라 1대 복원 실험 기준으로 1px이면 통과 지점 상하 오차가 약 22cm다.
- **기울기로 구한 초점거리**: 정보 파일의 화각으로 계산한 값과 비교한다. 다르면 화각 정보나 거리 측정을 의심한다.
- **던진 공의 지름 흔들림**: 프레임마다 잰 지름이 매끄러운 곡선에서 얼마나 벗어나는지(px).
- **번짐 길이**: 노출 자동과 1/2000초를 비교한다.

측정 방법의 한계:
- 공을 밝기가 균일한 원판으로 보고 잰다. 실밥, 그림자, 빛 반사가 있으면 치우칠 수 있고, 그 치우침이 곧 이 실험에서 재려는 것이다.
- 던진 공은 배경(프레임 중앙값)과의 차이로 찾으므로 카메라가 움직이면 안 된다. 던지는 사람이나 다른 움직임이 공보다 크게 잡히면 엉뚱한 것을 잴 수 있다. 프레임별 CSV의 위치(x, y)로 확인한다.
- 합성 영상(HEVC 압축 포함)에서는 지름 치우침 +0.06px, 번짐 길이 6.4px(실제 6px)로 쟀다. 실제 영상에서도 그럴지는 이 실험으로 확인한다.

## 이 영상으로 확인할 것
- 멈춘 공: 화면에서 잰 지름이 `초점거리 × 0.074m ÷ 거리`와 맞는가. 여기서 실제 초점거리(px)도 구한다.
- 움직이는 공: 진행 방향으로 얼마나 번지는가. 노출 자동과 1/2000초의 차이.
- 영상 압축 때문에 공 가장자리가 뭉개지는 정도.
- 240fps가 실제로 유지됐는가(정보 파일의 프레임 수와 시간).
